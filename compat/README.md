# compat

Data behind a page showing which Cardano tooling agrees with which, generated by running
real tool releases over the vectors already committed under `vectors/`. Everything here
is either an observation from actually running a tool, or a straight read of a public
registry; nothing in this directory is computed by hand.

## Why this exists

`cardano-binary`, the serialization library under `cardano-node`, `cardano-api` and
`cardano-cli`, frames a native script's sub-script list as a definite-length CBOR array
up to 23 children and an indefinite-length array from 24 up.
`cardano-serialization-lib` and MeshJS use definite length at every size. A script with
24 or more sub-scripts in one container therefore has two valid hashes, and which one a
given tool produces depends on which encoder it runs. See
[`spec/07-encoding-divergence.md`](../spec/07-encoding-divergence.md) for the full
account; this directory exists to keep watching whether that stays true as every tool
keeps shipping new versions.

## What this measures, and what it does not

Every result here comes from handing a tool the same JSON shape this project's own
model uses (`{ type: 'sig', keyHash }`, `{ type: 'all', scripts }`, and so on) and asking
it to build a native script and hash it. That is the "construct from JSON" path.

A tool that instead decodes an existing CBOR script and re-hashes those exact bytes can
follow a different rule (this project's own `scriptHashFromCbor` does exactly that, on
purpose: see `spec/07-encoding-divergence.md`). This directory does not measure that
path for any tool yet. If a tool's behavior turns out to depend on which of its own APIs
is used, the right fix is to register it twice, once per path, each independently run
and each with its own `id`, rather than picking one path and calling it "the" result for
that tool.

## `tools.json`

The registry of tools to watch. Each entry:

| Field            | Meaning                                                                                                 |
| ---------------- | ------------------------------------------------------------------------------------------------------- |
| `id`             | Stable identifier, also the directory name under `results/`.                                            |
| `displayName`    | Name for a rendered page.                                                                               |
| `homepage`       | Where the tool's source or release notes live.                                                          |
| `package`        | npm package name, for tools discovered or installed via npm.                                            |
| `adapter`        | Which installer/hasher this tool uses. See below.                                                       |
| `adapterOptions` | Small adapter-specific configuration, e.g. which function to call.                                      |
| `discovery`      | How to find new versions: `{ "type": "npm" }`, or `{ "type": "github-releases", "repo", "tagPrefix" }`. |
| `channels`       | Which of `current`, `previous`, `beta` to track for this tool.                                          |

Adding a tool that shares an existing adapter's API (another cardano-serialization-lib
fork, another library exposing the same `resolveNativeScriptHash(script) -> string`
shape MeshJS does) is adding an entry here. A tool with a genuinely different API needs
a new adapter under `src/compat/adapters/`.

### Adapters

- **`cardano-cli-binary`**: downloads the platform-matching release tarball from GitHub,
  verifies it against the release's own `sha256sums.txt`, and runs
  `cardano-cli hash script --script-file`.
- **`npm-csl`**: installs the npm package into an isolated scratch directory and drives
  cardano-serialization-lib's builder API (`NativeScript.new_script_all`,
  `ScriptNOfK.new`, and so on) in a child process next to that install.
- **`npm-native-script-json`**: installs the npm package and calls the function named in
  `adapterOptions.exportName` with the script's plain-JSON shape, converting timelock
  slots to a string first when `adapterOptions.slotEncoding` is `"string"`.

## Channels

`current` and `previous` are the two most recent stable releases; `beta` is a
pre-release version newer than `current`, i.e. an actual upcoming preview rather than a
pre-release for a line that has already shipped. A tool with no active beta simply has
no `beta` result for that run; a missing channel is not an error.

## `results/<tool>/<version>.json`

One file per tested version, keyed by exactly the version string that was installed.
Never hand-edited: a version is retested by running the watcher again, which produces a
new file if the version changed, or leaves the old one alone if it did not.

```json
{
  "formatVersion": 1,
  "tool": "cardano-cli",
  "version": "11.2.3.1",
  "channel": "current",
  "testedAt": "2026-09-15T23:20:35.203Z",
  "corpusDigest": "a6688f76c41e96e5bc1ebd45ad0bd148898d0bc8f3b5fdcca4c4059f",
  "arachneVersion": "arachne@0.1.0",
  "status": "tested",
  "framing": "cardanoBinary",
  "summary": { "total": 126, "agreed": 119, "diverged": 0, "refused": 7, "unsupported": 0 },
  "vectors": [
    { "id": "breadth/all-w002", "status": "agreed", "hash": "b834...", "matchedFraming": "both" }
  ]
}
```

| Field                      | Meaning                                                                                                                                                                                          |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `corpusDigest`             | `vectors/index.json`'s own digest at the time this ran. Two results are only directly comparable if this matches.                                                                                |
| `arachneVersion`           | This project's version that generated the corpus being tested against.                                                                                                                           |
| `status`                   | `"tested"` or `"untested"`. See below.                                                                                                                                                           |
| `framing`                  | `"definite"`, `"cardanoBinary"`, `"mixed"`, or `"undetermined"`, derived from the vectors below where the two encodings actually differ. Never asserted independently of the per-vector results. |
| `vectors[].status`         | `"agreed"`, `"diverged"`, `"refused"`, or `"unsupported"`. See below.                                                                                                                            |
| `vectors[].matchedFraming` | Which of the corpus's two recorded hashes the tool's answer matched: `"definite"`, `"cardanoBinary"`, `"both"` (the two coincide for this script), or `"neither"`.                               |

### When a tool could not be installed

```json
{
  "formatVersion": 1,
  "tool": "cardano-cli",
  "version": "99.0.0.0",
  "channel": "beta",
  "testedAt": "2026-09-15T23:20:35.203Z",
  "corpusDigest": "a6688f76c41e96e5bc1ebd45ad0bd148898d0bc8f3b5fdcca4c4059f",
  "arachneVersion": "arachne@0.1.0",
  "status": "untested",
  "reason": "GET https://github.com/.../cardano-cli-99.0.0.0-x86_64-linux.tar.gz failed with 404",
  "framing": null,
  "vectors": [],
  "summary": { "total": 0, "agreed": 0, "diverged": 0, "refused": 0, "unsupported": 0 }
}
```

`untested` is a first-class result, not a missing file: a version that cannot be
installed still gets a record, with `reason` carrying whatever error the install step
produced, verbatim. There is no status that means "we did not check"; the absence of a
result file for a version simply means that version has not been resolved yet.

### Per-vector status

- **`agreed`**: the tool's hash matches one of the two hashes already recorded on that
  vector. Neither of the two is canonical, so matching either one counts.
- **`diverged`**: the tool produced a hash, and it matches neither recorded hash. This is
  the finding the whole encoding question turns on: a third value for a script that
  should only ever have (at most) two.
- **`refused`**: the tool ran and declined to answer, with its own verbatim error text
  in `error`. cardano-cli validates threshold shapes more strictly than the ledger does,
  so some vectors are refused by design; that refusal pattern is itself recorded, not
  hidden.
- **`unsupported`**: reserved for a construct an adapter recognizes ahead of time as
  unrepresentable in a tool's API at all, as opposed to an attempt the tool itself
  rejected. No result committed so far uses it.

### Errors are verbatim

`reason` and `vectors[].error` are the tool's own text, truncated only where the
upstream adapter already truncates (see `src/vectors/cardano-cli.ts`'s 300-character
cap, mirrored here). Never normalized, reworded or summarized: a prettified error
destroys the finding it is reporting.

## Rendering a page from this

For one tool, read every file under `results/<tool>/`, sort by version, and the
`channel` field already tells you which one is current/previous/beta as of when it ran.
For a compatibility matrix across tools, `framing` is the single field to compare; a
`mixed` or `undetermined` value on a version that used to resolve cleanly is worth
surfacing on its own, not averaged away.

## How results get here

`.github/workflows/upstream-watch.yml` runs daily: it resolves every registered tool's
current/previous/beta versions, checks which ones have no result file yet, runs those,
and opens a pull request with the new files. It never pushes to `main` directly. The
same logic runs locally:

```
npx tsx scripts/compat-check.ts              # what is pending, without installing anything
npx tsx scripts/compat-run.ts <tool> <version> <channel>   # run and record one version
npx tsx scripts/compat-watch.ts              # run everything pending and write a PR title/body
npx tsx scripts/compat-watch.ts --dry-run    # the same, without installing or writing results
```
